    Three things the measurements said that I did not expect

    written up as errors 11, 12 & 13

    Error 11

    One metric ranked the worst prompt first

    v1 scores highest on ROUGE-L, and it is the only version that invents a closing sentence and ignores the length limit. It writes four sentences where the others write two, and more text means more overlap with the reference. ROUGE rewarded it for rambling.

    VersionROUGE-LComposite
    v10.5820.449
    v20.4980.650
    v30.5630.825
    v40.5630.825

    The weights were set before the comparison ran. This is why the gate uses a composite of four measures and not one number.

    Error 13

    The prompts were throwing away half the input

    Text containing Summary: silently truncated the input for v1 and v2. The output was a fluent, correct-looking summary of the surviving half, with nothing anywhere saying the rest had gone. No attacker needed — minutes and email threads contain that word routinely.

    Adding <text> tags in v3 did not fix it. It swapped the trigger to </text>.

    The fix, and its limit

    Delimiters do not prevent injection — they make it preventable

    This is SQL injection. User text concatenated into a structured string, with nothing checking whether the text contains the structure. So it takes the same fix: escape where data meets structure. render_prompt now does, and v3 and v4 went from 67% to 100%.

    v1 and v2 cannot be fixed this way. Their structure is the word Summary:, which is ordinary English — escaping it would corrupt any document that legitimately contains it.
